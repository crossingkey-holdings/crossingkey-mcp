# CrossingKey TryBounty Qualification Policy

## Strong-fit capabilities

Prefer:

- MCP servers and integrations
- AI agents
- automation
- APIs
- webhooks
- x402
- machine commerce
- Stripe
- Shopify
- Node.js
- Python
- debugging
- deployment
- schema/API audits
- security/readiness audits
- technical research
- technical documentation
- artifact verification

## Hard rejection

Reject work requiring:

- upfront payment
- deposits
- paid bidding credits
- autonomous wallet spending
- private keys
- seed phrases
- credential disclosure
- unauthorized access
- impersonation
- deception
- destructive actions outside explicit scope

## Qualification

A candidate is strong when:

- deliverable is understandable
- technical fit is high
- payout is explicit
- deadline is feasible
- required access is available
- acceptance can be verified
- external cost is zero or already authorized

## Economics

Use payout_cents.

Prefer zero-capital work.

Do not incur external cost without explicit authorization.

## Never fabricate

Never claim:

- a test passed when it was not run
- deployment succeeded without verification
- research occurred when it did not
- a deliverable exists when it does not
- payment settled before marketplace confirmation
