## Remediation decision

No `npm audit fix --force`, unsupported override, privileged cache change, or
system-wide reconfiguration was applied. The `EROFS` cache error was worked
around with an isolated writable cache only. The lockfile was regenerated by
explicit exact-version upgrades, followed by `npm ci --ignore-scripts`.

## Existing runtime mitigations

- SSRF and private-address rejection are enforced before outbound provider and
  audit requests.
- HTTP redirects are rejected for provider/audit fetches.
- Response bodies are bounded to 256 KiB for audit/provider paths.
- The service does not expose an OAuth client flow.
- Payment verification, settlement, idempotency, replay, receipts, and
  receiver-only controls remain in the existing tested path.

## Reachability and residual verification

The Express proxy-address parser and AJV/URI validation paths are reachable in
normal HTTP/schema processing and are therefore treated as production-relevant;
they are patched in this worktree. The SDK OAuth advisory concerned a client
credential-forwarding surface; source inspection found the service using the
SDK server/transport surfaces without an enabled OAuth client flow. This is a
source/dependency-graph assessment, not a formal exploitability certification.

The isolated full suite, targeted security tests, payment lifecycle coverage,
and startup probe passed after the upgrades. Production dependency state and
the unreadable systemd drop-in remain unverified and require a separately
authorized release operation.
